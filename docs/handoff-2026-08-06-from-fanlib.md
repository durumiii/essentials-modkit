# 판정 코드의 판을 밖에 알린다 (fanlib 요청, 2026-08-06)

## 무엇이 들어왔나

`modkit/stamp.py` 하나와 시험 다섯이다. `stamp.fit_stamp()`는 모드가 이 설치본에 맞는지
따지는 코드의 판을 짧은 문자열로 돌려준다. 계약은 SPEC 5.5절에 등재했다.

## 왜 필요했나

fanlib은 모드 판정 결과를 화면마다 다시 세지 않으려고 기억해 둔다. 그 기억의 열쇠는
게임 폴더의 스크립트 파일과 모드 보관소만 본다. **우리가 판정 규칙을 고쳐도 게임 파일과
보관소는 그대로라 열쇠 값이 안 바뀐다.**

지금까지는 이 구멍이 안 드러났다. fanlib의 기억이 프로세스 안에만 살아서, 서버를 껐다
켜면 통째로 사라지고 새 규칙으로 다시 셌기 때문이다. 그런데 fanlib이 그 기억을 디스크로
옮기려 한다. 옮기는 순간 **디스크에 남은 옛 판정이 새 규칙을 이긴다.**

fanlib이 디스크로 옮기려는 까닭은 값이 크기 때문이다. 실측(2026-08-06, Windows,
게임 열아홉·모드 예순셋):

| 무엇 | 걸린 시간 |
|---|---|
| `modfit.check` 전부 | 9,393ms |
| `modstore.shelf` 전부 | 176ms |
| `scripts.sources` 전부 | 447ms |

fanlib은 최근 트레이 아이콘이 서버 수명을 쥐게 되면서 서버를 자주 껐다 켠다. 그래서 열 때마다
9초를 다시 냈다.

## 왜 `__version__`이 아닌가

손으로 올리는 번호는 올리는 것을 한 번 잊으면 바로 그 사고가 난다. 판정에 끼는 파일들의
내용에서 뽑으면 사람이 기억할 것이 없다.

## 우리가 지켜야 할 것 하나

**판정 규칙을 `stamp.JUDGES`에 없는 파일로 옮기면 이 계약이 조용히 깨진다.** 지금 목록은
`modfit.py` · `modassets.py` · `modstore.py` · `scripts.py`다. 판정에 끼는 파일을 새로
만들거나 규칙을 다른 파일로 옮길 때 목록도 같이 고친다. 깨져도 우리 시험은 통과하고,
fanlib 화면에 옛 판정이 뜨는 것으로만 드러난다.

## 값이 무엇을 뜻하는지는 약속하지 않았다

같으면 같은 판, 다르면 다른 판. 그뿐이다. 자릿수도, 만드는 법도, 값의 뜻도 바깥이 기대면
안 된다고 SPEC에 적었다.

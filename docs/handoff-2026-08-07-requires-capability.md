# `requires`가 이름만 받아 「한글 폰트 아무거나」를 못 적는다 (pokemon-z 요청, 2026-08-07)

## 한 줄

한 모드를 번역과 폰트로 가르려는데, 번역 모드가 필요로 하는 것은 **특정 폰트 모드가 아니라
「한글이 든 폰트를 제공하는 모드 아무거나」**다. 지금 `requires`는 모드 **이름**만 받아
이 관계를 적을 수 없다. 능력 선언(`provides`)을 더해 달라는 요청이다.

확정도: 코드 실측. `declare.gate`(declare.py:23-40)가 `requires`의 각 항목을
`installed_names`(설치된 모드 **이름** 목록)와 문자열로 견준다. `provides`·capability 류의
축은 코드에도 SPEC에도 없다(`grep -rn "provides\|capabilit" modkit/` → 0건).

## 왜 필요한가 — 실제 사례

포켓몬 Z 한글패치를 두 모드로 가른다. 근거는 결합이다.

| 모드 | 담는 것 |
|---|---|
| 한글패치 (Runa) | 번역표 `korean.dat` · 번역된 `Scripts.rxdata` · 번역 자산 |
| 픽셀 폰트 | 한글 든 폰트 16벌 · `mkxp.json` · 글자 그림자·굵게 스크립트 |

- 그림자 기본값(1.25픽셀 · 반겹 알파 150)은 **획이 1픽셀인 픽셀 폰트를 전제로** 맞춘 값이라
  폰트와 한 몸이다. 그래서 렌더링 쪽으로 묶었다.
- 의존은 한 방향이다. **번역은 한글 폰트 없이 스탠드얼론이 안 된다**(글자가 네모로 떨어진다).
  반대로 폰트 모드는 번역이 없어도 멀쩡하다(스페인어가 픽셀 폰트로 나온다).

그런데 번역 모드가 필요로 하는 것은 우리 픽셀 폰트 모드가 아니다. **한글 글리프를 들고
게임이 요청하는 패밀리명을 차지하는 모드라면 무엇이든 된다** — 갈무리를 쓰는 판, 다른
픽셀 폰트를 쓰는 판이 얼마든지 있을 수 있고 실제로 이 프로젝트도 갈무리판에서 옮겨 왔다.

## 지금 적을 수 있는 것과 그 문제

| 방법 | 문제 |
|---|---|
| `"requires": ["픽셀 폰트 모드 이름"]` | 다른 한글 폰트 모드를 쓰는 사람이 **차단된다**. `--force`로 뚫으면 차단의 뜻이 사라진다 |
| `requires` 없이 둔다 | 폰트 없이 설치돼 글자가 네모가 된다. modkit에는 「없어서 문제」를 알리는 경고 장치가 없다(있는 것은 `touches` 겹침 경고뿐) — **침묵으로 깨진다** |
| 폰트를 번역 모드가 도로 안는다 | 결합도가 낮은 것을 큰 모드에 흡수시키는 방향. 따로 끄고 켤 수 없어진다 |

## 부탁 — 능력 선언

카드에 `provides`(문자열 목록)를 더하고, `requires`가 **이름 또는 능력**을 받게 한다.

```json
// 픽셀 폰트 모드
"provides": ["hangul-font"]

// 한글패치 (Runa)
"requires": ["hangul-font"]
```

`gate`에서 검사 대상 집합을 「설치된 이름」에서 「설치된 이름 ∪ 그들의 `provides` 합집합」으로
넓히면 된다. 이름으로 거는 기존 카드는 그대로 통과한다(이름 집합이 부분집합이라).

같이 정해 주었으면 하는 것 넷.

1. **`order.after`도 능력을 받는가.** 지금 자동 배치는 이름 기준이다(SPEC 3절). 능력으로
   적으면 「그 능력을 제공하는 설치된 모드」로 풀어야 하는데, 둘 이상이면 어느 것 뒤인지가
   모호해진다. 우선 `requires`만 넓히고 `order`는 이름으로 두는 쪽이 안전해 보인다.
2. **능력 이름을 누가 정하는가.** 지금 필요한 것은 `hangul-font` 하나뿐이라 카드에 적힌
   문자열을 그대로 쓰면 충분하다. 표준 목록을 두면 오타가 조용한 차단이 되므로,
   `lint`가 **알려진 능력 목록에 없는 이름을 권장 경고**로 알리는 정도가 적당해 보인다.
3. **`conflicts`도 능력을 받는가.** 「같은 능력을 제공하는 모드끼리는 충돌」이 자연스러운
   자리가 있다(폰트 모드 둘이 같은 파일을 덮는다). 다만 지금은 `touches` 겹침 경고가
   그 자리를 이미 얼마간 맡고 있어, 필요해질 때 넣는 편이 낫다고 본다.
4. **`applied_ratio` 판정과의 관계.** 에셋형 모드는 설치 여부를 파일 대조로 답한다
   (`modassets.applied`). 능력 제공자가 「부분 덮임」 상태일 때 `requires`를 만족한 것으로
   볼지가 애매하다. `present()`가 이미 부분 일치도 설치로 세므로 그대로 따르면 될 것 같다.

## 규모

`declare.gate`의 몇 줄과 SPEC 2절의 카드 필드 표 한 줄, `lint`의 권장 검사 하나. 기존
카드의 동작은 안 바뀐다. 요청한 쪽 판단으로는 큰 변경이 아니다.

## 참고

- 이 가름의 전제인 「그림자·굵게가 잡는 코어 섹션을 한글패치가 안 건드린다」는 실측으로
  확인했다 — `SpriteWindow`·`DrawText`의 md5가 순정과 패치판에서 같다(한글패치가 다시
  쓰는 섹션은 공통 236개 중 30개인데 그 둘은 거기 없다). 그래서 폰트 모드는 순정에서
  그대로 서고, 한글패치를 `requires`로 걸 이유가 없다.
